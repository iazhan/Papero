# 同步

Papero 的同步是**文件级的三方同步**。同步单位就是文件：Markdown、图片、PDF、白板
都是普通文件，因此远端可以是任何能存文件的地方。

四种远端（`internal/sync`）：

| 远端 | 适合 | 实现 |
| --- | --- | --- |
| `dir` | iCloud、OneDrive、坚果云客户端、Syncthing、U 盘 | 直接读写那个文件夹 |
| `git` | 想用 Git 管版本、想在 GitHub 上看历史 | 调用系统 `git`，另建一份副本推送 |
| `repo` | 知识库本身就是 git 仓库、已经推过 GitHub | 直接用库自己的仓库，什么都不用填 |
| `webdav` | 坚果云、群晖、Nextcloud、ownCloud 这类没有本地文件夹的网盘 | HTTP：PROPFIND 列目录、GET、PUT、DELETE、MKCOL |

自建的 HTTP 服务移除过（备份在 `ref/_removed/self-hosted-sync/`）。

`git` 远端的令牌**不进仓库地址**：拼进 URL 时 git 会把它原样写进副本的 `.git/config`，
而副本就在知识库里，整个文件夹同步出去就带走了。令牌走 `-c http.extraheader=…`，只作用
于那一条命令；发现老副本的 config 里还留着令牌时，下一次同步自动换成干净地址。

### 本库仓库

知识库本身就是 git 仓库、并且已经 `git push` 过 GitHub 时，远端选「本库仓库」：
**什么都不用填**。仓库从 `origin` 读，分支从 `HEAD` 读，令牌也不需要——`git` 会用系统里
已经配好的凭据（credential helper 或 SSH key）。

它和 `git` 远端的区别是根本性的：`git` 另建一份副本（`.papero/git`）当远端，所以要填
仓库、分支、令牌；这里直接用你的工作区，读的是 `origin/<分支>` 那棵树。

| 做法 | 为什么 |
| --- | --- |
| `List` 读 `origin/<分支>` 的树，不读工作区 | 读工作区的话两端永远一样，什么都不会同步 |
| 每文件版本用 blob SHA（`ls-tree` 报的就是它） | 天生就是「这一版是哪一版」的令牌，不用另存 |
| `git commit -m … -- <本轮碰过的路径>` | 不带 pathspec 的 commit 会把你自己暂存的东西一起提交 |
| 从不 reset / stash / checkout / 切分支 | 工作区是你的，Papero 只往里加一笔提交 |
| 被 `.gitignore` 忽略的文件不同步 | 它们进不了仓库，也就到不了远端；硬同步只会每轮失败或被当成「远端删了」 |

四个前提不满足时说清楚原因，不用含糊的 git 报错顶替：库根不是仓库根（是子目录）、
没有 `origin`、`detached HEAD`、没配 `user.name`/`user.email`。

两个已知边界：

- **子模块不同步**：树里它是 `commit` 不是 `blob`，只跳过，不递归。
- **`core.autocrlf` 开着时**（Windows 上 git 的默认值），版本令牌走
  `git hash-object --path=<路径>` 让 git 自己按转换规则算；否则工作区是 CRLF、仓库里
  是 LF，每轮同步都会把文件重下一遍、行尾还被悄悄改成 LF。

建议把 `.papero/` 写进 `.gitignore`：同步状态与 `.trash` 没必要进仓库。

### WebDAV

地址填到**同步根目录**，例如 `https://dav.jianguoyun.com/dav/Papero`。根目录不存在会
自动建；但它的上一级（`/dav`）必须在网盘里先有——替用户在账号里造一串目录不合适，所以
那一步会报错并说清楚。用户名空 = 不要登录，密码用网盘给的「应用密码」。

| 做法 | 为什么 |
| --- | --- |
| 逐层 `PROPFIND Depth: 1`，遇到子目录再往下 | `Depth: infinity` 很多服务器直接禁用，一次拿整棵树在大库上也慢 |
| 版本用 ETag，写时带 `If-Match` | 两台设备同时改同一个文件，后写的那次被 412 拒掉，而不是悄悄盖上去 |
| PUT 前逐级 `MKCOL`，建过的目录记在内存里 | WebDAV 不会替你建父目录；一个目录几百个文件时不能每个都建一遍 |
| GET 带 `Accept-Encoding: identity` | 压缩会换掉 ETag，返回的字节也不是原文（真被压了会自己解 gzip） |
| 认证只支持 Basic | 网盘的「应用密码」走的就是 Basic；Digest 要做一次挑战往返，没做 |

被 412 拒绝的那次同步**不落状态**，下一次重新比对；两边都改过的文件仍然按常规冲突处理
（远端为准 + 本地存副本）。密码是明文存在本机配置里的（和 GitHub 令牌一样）：它要发给
服务器，只能是原文。

### 服务器限速，与一个坏文件

坚果云对 WebDAV 有请求频率限制（每 30 分钟 600 次），超了回 `503` 加
`BlockedTemporarily`。一个八百多篇的库第一次上传，光 PUT 就要八百多次，一个窗口装不下。

所以限速时的规则是：**整轮停下，但已经做完的照常记状态**。过二三十分钟再同步一次，
会从上次停的地方接着传，不从零开始；第一次接一个空远端要分几轮，之后每轮只有改动的那
几个文件。限速不是「某个文件坏了」，也不会被当成一个文件的失败去逐个重试。

其它错误（服务器拒绝某个路径、本地文件读不出来）只影响那一个文件：记进
`Result.Failed`，其余照常同步，状态栏说「失败 N：<第一条原因>」。下一轮会再试它。

设置页的**测试连接**做一次轻量的探路：文件夹看得到就读一遍文件数，Git 用 `ls-remote`
只问不拉，WebDAV 用一次 PROPFIND，本库仓库额外报出是哪个仓库、哪个分支。三种情况分得开——连得上、远端还没有文件、同步位置
还不存在（第一次同步会建）。WebDAV 的目录不在时还会看一眼上一级：上一级在就是「还没建」，
上一级也不在就是地址写错了。

## 算法

对每个文件，记下**上次同步时**的本地摘要与远端摘要（SHA-256），与当前状态比对：

| 本地 | 远端 | 结果 |
| --- | --- | --- |
| 没变 | 没变 | 什么也不做 |
| 变了 | 没变 | **上传**；本地删了就在远端也删 |
| 没变 | 变了 | **下载**；远端删了就本地移进 `.trash` |
| 两边都变了，内容相同 | | 直接记为已同步（两边都删了就删掉这条记录） |
| 两边都变了，内容不同 | | **冲突**：远端版本成为正式文件，本地改动另存为<br>`名字 (冲突 2026-11-17 23-00-00).md` |
| 远端删了，本地改了 | | 本地保留并重新上传（不丢用户改动） |

冲突副本不会被自动删除，也不会被下一次同步覆盖——它作为一个新文件被上传，
用户可以在任何设备上看到并决定留哪个。

### 第一次接上一个已经有文件的远端

「两边都有、内容不同」在**第一次**同步时不算冲突。这时远端为准，本地那一版整批收进
`.papero/join-2026-11-17-230000/`，文件名与目录结构保持不变。理由是接一个已经有
笔记的网盘时，逐文件生成「(冲突 …)」会让文稿树一下散出几百个副本，而用户要的通常是
「先看看旧的在哪」，一个目录就够了。状态栏会说「加入 N · 本地版本已存到 …」。

远端为空时不涉及这一条：本地文件照常上传。

### 三个保护

- **删除刹车**：如果一次同步发现远端「消失」了 20 个以上文件、且超过本地状态记录的
  十分之一，说明更可能是服务端出问题（而不是用户删了东西），这时**推迟删除**，
  只统计 `Skipped`，不动本地。
- **推不出去就不落状态**：推送失败（比如另一台设备刚好抢先提交）时状态文件不前进。
  git 的文件先进副本、`Flush` 成功才算发出去；状态要是记成「已同步」，下一次副本被
  重置回远端版本，本地这个文件就会被当成「远端删了」。同步被中途取消时同理：文件夹
  远端可以留下已完成的进度（写进去就是写完了），git 不留。
- **不碰内部文件**：`.git`、`.trash`、`.papero`、`node_modules`、`.obsidian`
  与临时文件一律不同步，避免把版本库和同步状态本身也传来传去。

## 哪些文件不同步

有三层，从硬到软：

1. **永远忽略**：`.git`、`.trash`、`.papero`、`.obsidian`、`node_modules`，以及
   `.tmp` 文件。按**任意一段**路径判断，所以 `sub/.git/config`（嵌套仓库）也不会被传。
2. **忽略点开头**（开关）：`.nestnote`、`.marking`、`.nexus`、`.ok` 这类工具目录。
   开了之后，这些目录整棵跳过——本地不传、云端也不下来（已经传上去的不会删，只是不再动）。
3. **按 .gitignore**（开关）：读知识库**根目录**那一个 `.gitignore`。

`.gitignore` 只认常用的写法：`#` 注释、空行、`!` 取反、结尾 `/` 只匹配目录、开头 `/`
锚定根目录、`*` `?`、`**`。不认的：`\` 转义、子目录里的 `.gitignore`（git 会读，我们
不读）、`!` 抢救被排除目录里的文件（git 也一样救不回来）。

两边都过滤：本地扫描和远端文件表用的是同一套规则，所以打开开关不会造成「本地认为
删了、远端还在」的来回。已经同步上去的点文件留在云端不动。

## 从云端拉取

`Engine.Pull` 只往下拿：云端多出来的、远端更新过的文件下载下来。三条边界——

- **不上传**：本地独有的文件不动，等你点同步时才传；
- **不删除**：云端没有的文件不会把本地删掉；
- **两边都改过的文件不碰**：留给一次完整同步去合并（那边会保留本地副本）。

覆盖本地之前，本地那一版进 `.papero/before-pull-<时间>/`，路径结构不变。

设置里勾「打开时先从云端拉取一遍」，每次打开 Papero 都会先拉一次；多台设备编同一个
库时，先拿到别人的改动再动手。拉完会重载打开着的文稿——有未保存改动的跳过（不能被
一次后台拉取冲掉），它们留给下一次同步去合并。

打开时那次是静默的：没有更新就不说话。手动点「从云端拉取」才会明确回一句
「云端没有更新」。

## 状态文件

同步状态存在知识库内的 `.papero/sync.json`：

```json
{
  "remote": "dir:D:\\Notes\\Shared",
  "files": {
    "notes/a.md": { "local": "…", "remote": "…" }
  }
}
```

它跟着知识库走，但本身不参与同步。

`remote` 是远端的**完整描述**（`Sync.Remote.Descriptor()`）：`dir:` 加绝对路径，
`git:` 加 `owner/name#分支`，`repo:` 加库根与分支，`webdav:` 加地址与账号。换文件夹、换仓库、换分支、
换地址都会让旧状态作废、重新按「第一次接上」比对。只记类型是不够的——换成一个空文件夹
时，旧状态里「远端还有这些文件」会被读成「文件全被删了」，整个库被搬进 `.trash`。
旧版本留下的 `"dir"`/`"git"` 按类型认下来，不清空老用户的记录。
