# 架构

Papero 是一个 Go 二进制。窗口由 [MyGo](https://github.com/egoist/mygo) 的 `ui` 包在 GPU 上
绘制（macOS 用 Metal，Windows 用 Direct3D 11，Linux 用 OpenGL），没有 WebView、没有
JavaScript，也没有 cgo。

```
main.go ──▶ internal/app ──┬──▶ internal/vault     知识库：扫描、类型、安全读写
                           ├──▶ internal/pdfview    PDF 渲染（folio 封装）
                           ├──▶ internal/docx       .docx → Markdown
                           ├──▶ internal/plugin     插件清单与宿主契约
                           │      └── internal/plugins/board   白板（内置插件）
                           ├──▶ internal/sync       文件级三方同步
                           └──▶ internal/config     本机设置
                    │
                    ▼
        github.com/egoist/mygo（mygo、ui、ui/editor、ui/markdown）
```

**领域包不依赖 MyGo。** `vault`、`pdf`、`docx`、`plugin`、`sync` 都不 import `ui`，
因此它们能脱离窗口单元测试，也能被将来的 CLI、服务端或插件宿主复用。
只有 `app` 与 `plugins/board` 的绘制部分用到 `ui`。

## 主题与字体

Papero 不用 MyGo 的默认主题，而是在每帧开头 `c.SetTheme(paperoTheme(dark))`
换上一套自己的（`internal/app/theme.go`）：

- **配色**：中性灰。窗口与侧栏是浅灰，文稿是白纸，分隔线很淡；强调色只用在链接、
  主按钮、焦点环与**内容选区**（编辑器文本、块选区、PDF 批注行）上，
  外壳的选中（侧栏行、标签）仍然是灰底。深色模式是同一套灰的深色版本。
  选区是强调色压到低透明度（浅色 16%、深色 36%），用户把强调色选成浅黄、
  米白这类接近纸色的颜色时，`theme` 会自动把它推深，免得选区看不见。
- **字体**：界面用系统的无衬线字体（Windows 上是 Segoe UI，macOS 上是苹方），
  源码编辑器用等宽字体（Cascadia / Consolas / SF Mono）。
- **字号**：主题基准 13，界面里的具体尺寸按部位微调（动作行 12.5、树 12.5、
  状态栏 11）。

换主题的影响面比想象中大：`ui/markdown` 的正文颜色、`ui/editor` 的高亮、
按钮与输入框都从主题取色，所以这一处改完，整窗口的观感是一致的。
外壳自己还需要几个部位色（卡片、标签栏、选中底色），由 `chromeFor(theme)` 映射出来，
不另立一套色板。

## 数据模型：文件是唯一真相

知识库 = 一个文件夹。一篇笔记 = 一个 `.md` 文件。附件（图片、PDF、Word、白板）
就是同目录或子目录里的普通文件。

这样做的好处很实际：

- 用户在 Papero 之外改文件，Papero 重新扫描就能看到；反过来也一样。
- 同步不需要理解 Papero 的格式，只要传文件。
- 迁移成本为零：删掉 Papero，笔记还在。

代价是 Papero 不能像数据库那样存储「块 ID、属性、关系」这类结构。
因此**额外信息一律写在 Markdown 里**（frontmatter、`[[双链]]`、标准 HTML），
或者写在知识库的隐藏目录 `.papero/`（同步状态、Git 副本），
绝不污染正文。

## 界面：立即模式

MyGo 的 `ui` 是立即模式：`App.view(c)` 每一帧从状态重建整个窗口，画完即丢。
所以：

- 所有界面状态都放在 `App` 里（`tabs`、`active`、`filter`、`sidebarW`…）；
- 不要保存 `ui.Element`（它只属于一次构建）；
- 需要跨帧保留的控件状态（滚动位置、编辑器缓冲区、Markdown 排版缓存）由应用自己持有
  ——见 `tab` 结构里的 `buf`、`state`、`md`、`pdfKey`。

后台工作（同步）跑在 goroutine 里，结果通过 `win.Update(func(){...})` 回到主线程。

### 窗口结构

标题栏是隐藏的（`TitleBarStyle: mygo.TitleBarHidden`）：视图自己画最上面一行。
左边是侧栏开关、快速跳转、命令面板，以及 文件 / 编辑 / 视图 / 帮助 四个菜单
（`Element.PopoverMenuButton` 在窗口内绘制，和应用的浮层观感一致）；
右边是窗口按钮（macOS 用系统的红绿灯，其他平台用 `HideWindowButtons` 自绘）。
软件名放在侧栏顶部。标题栏、侧栏顶部与标签栏都可以拖动窗口。

```
┌──────────────────────────────────────────────────────┐
│ ☰  ⌕  ⌘   文件 编辑 视图 帮助              ─  □  ✕    │  titleBar
├───────────────┬──────────────────────────────────────┤
│ Papero 0.1    │  标签 ×            ＋                │  tabBar（卡片顶部）
│ ⌕ 快速搜索    ├──────────────────────────────────────┤
│ ▤ 打开知识库  │                                      │
│ ✦ 发现        │            正文（卡片）               │  content
│ 文档  大纲   ＋│                                      │
│               │                                      │
│ 目录树 / 大纲  │                                      │
│ 最近打开      ├──────────────────────────────────────┤
│ 工作区间      │ 路径      分栏 预览 源码 已保存 …     │  statusBar
│ ⚙ 设置        │                                      │
└───────────────┴──────────────────────────────────────┘
```

侧栏分三段：**动作**（新建文稿、快速搜索、打开知识库、知识图谱、发现）、**当前知识库**
（文档 / 大纲的轻量切换、目录树或大纲）、**底部**（最近打开、工作区间、设置与统计）。
侧栏里不放搜索框：搜索由「快速搜索」（Ctrl+K）和标题栏的放大镜承担，
两者都是跨全库的模糊匹配，比逐层过滤目录树更好用。
「发现」是留给知识图谱与插件市场的入口，现在里面能管理已安装的插件。

侧栏开合是 240ms 的滑动：面板整体往左退、外框宽度同步收放（`App.sidebarP`，
0 收起 1 展开），正文卡片跟着涨落；顶栏左边那块「品牌 + 展开按钮」按同一个进度
让出宽度，标签才会跟着卡片平移，而不是等滑完才跳一格。进度挂在根行上——收起后
侧栏整块不在树里，动画状态存不住，只能存在一个每帧都在的元素上。

那块内容比容器窄的时候会被右边裁掉，硬裁会在中途露出「Pa」这种半个词，所以按宽度
分两段淡入：品牌名在进度 0.45（刚好整个露出）开始显，按钮与分隔线在 0.2（自身完整）
开始显。静止的两种状态都不套透明度，画面与没有动效时一致。

### 一帧里发生什么

1. `shortcuts(c)` 处理窗口级快捷键；
2. `titleBar(c)` 画侧栏开关、搜索、命令面板、菜单与窗口按钮；
3. `sidebar(c)` 画动作、目录树 / 大纲、最近打开、工作区间与统计；
4. `tabBar(c)` 画卡片顶部的标签；
4. `content(c)` 按当前文稿类型分派：
   - `markdownTab` —— 分栏 / 预览 / 源码；
   - `textTab` —— 代码编辑器；
   - `imageTab` —— `ui.Image`，可缩放；
   - `wordTab` —— docx 转出的 Markdown 走 `ui/markdown`；
   - `pdfTab` —— `Painter` 逐块绘制文字与图片；
   - `boardTab` —— `Painter` 绘制白板元素；
5. `statusBar(c)` 画路径、保存状态、编码、行数与显示方式；
6. `overlays(c)` 画快速跳转、发现、设置与提示条。

### 右键菜单与标签栏

目录树的行、标签栏的标签都有右键菜单（`Element.PopoverMenu`，窗口内绘制）：
文稿可以打开、重命名、复制相对路径、在系统文件管理器中显示、移到知识库的 `.trash`；
目录还能新建文稿 / 文件夹；标签还能「关闭其他」「关闭右侧」。中键点标签直接关闭，
和浏览器一致。

标签栏不显示滚动条（它会压在标签上），标签溢出时两侧出现 ‹ › 箭头，
到头的一侧变淡；切换标签时还会自动把它滚进视野。这三件事合起来，
标签再多也不会出现「看不见也点不到」的标签。

### 编辑器

Markdown 与纯文本用 MyGo 的 `ui/editor`：它提供语法高亮、多光标、软换行、撤销、
折叠、查找替换，并且只对视口内的行排版，因此大文件也能流畅编辑。
`editor.Buffer` 自带撤销栈与 `Modified()`，保存后调用 `MarkSaved()`。

预览用 `ui/markdown`：CommonMark + GFM（表格、任务列表、删除线、脚注）与数学公式，
每帧只重新解析变化的部分。`markdown.Options` 提供了三个挂钩：

- `LoadImage` —— 用 `markdown.FileImages(文档所在目录)`，图片相对路径就能显示；
- `OnLink` —— 站内 `.md` 直接打开，`#锚点` 滚动到标题，其余交给系统浏览器；
- `OnTask` —— 预览里的复选框可点，改动写回 Markdown 原文（`[ ]` ↔ `[x]`）。

### 实时排版：走向所见即所得的第一步

源码编辑器里有一层「实时排版」（`livepreview.go`），它不改 Markdown 的语法，
只是借编辑器的两个能力把标记**画淡**：

| 能力 | 用途 |
| --- | --- |
| `State.SetLineStyles` | 标题行换成更大更粗的无衬线字体（按 `#` 数量定字号） |
| `State.SetReplacements` | 把 `**`、`*`、`~~`、`` ` ``、`[[ ]]`、`](地址)` 换成空，把 `[ ]` 画成可点复选框 |

几条原则：

- **光标所在的行保留原始标记**，否则没法编辑；移开就又「渲染」。
- 只处理**可见行**（`VisibleLines`），长文档没有额外开销；超过 512 KB 的文稿直接关掉。
- 代码围栏里的内容原样保留。
- 复选框是 `Interactive` 的替换元素，点击直接改缓冲区（`[ ]` ↔ `[x]`），算一步撤销。

它给出的是「读起来接近渲染结果」的源码，而不是真正的块编辑器：
行内加粗仍然只是「去掉了星号」，不会变成粗体字（编辑器的替换只能换文字与颜色，
不能给片段换字体）。真正的所见即所得还是需要块模型，见下面的取舍。

### 标题栏与标签栏

分成两行，各司其职：

```
☰ 🔍 ⌘ │ 文件 编辑 视图 帮助                    欢迎          │ — □ ✕   ← 40px 标题栏
┌──────────────────────────────────────────────────────────┐
│ [欢迎 ×][工具 ×]                                        + │          ← 卡片里的标签栏 38px
├──────────────────────────────────────────────────────────┤
│  正文 …                                                   │
└──────────────────────────────────────────────────────────┘
```

- **窗口按钮**自己画（`HideWindowButtons`，两个窗口都如此，否则会同时出现系统和自绘两套）：
  46 宽、贴右上角、无圆角；图形用 IconMCP 的四个——`minus`（最小化）、
  `maximize`（非最大化时，向外扩）、`minimize`（已最大化时，向内收＝还原）、`close`（关闭），
  关闭悬停变红 `#c42b1c`。中间那颗按 `win.IsMaximized()` 每帧切换，
  点它时相应调用 `Maximize()` 或 `Unmaximize()`。
- **编辑菜单**不用 mygo 的 `m.EditItems()`：它只在焦点是 `TextInput` 时才有内容，
  而这里的焦点是块编辑器 / 源码编辑器，菜单会变成空的、点开什么都没有
  （空菜单还会卡住「悬停切换」的状态）。现在自己列：撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选
  （`State` 与 `Buffer` 的接口）＋ 快速跳转 / 命令面板。
- **菜单**：四个菜单各有自己的「开着吗」标志（`PopoverMenuButtonOptions.Open`），
  已经开着菜单时，鼠标划到另一个菜单上就直接切过去（系统菜单栏的常规行为），
  正在显示的那个按钮自己也亮着。
  这里有个坑：MyGo 是**按事件重绘**的，把 `Open` 在按钮 build 之后才改，要等下一次
  鼠标移动才会画出来——表现成「切过去没反应，再动一下才出现」。所以两件事一起做：
  用上一帧记下的 `menuHover` 在 build **之前**拨开关（mygo 见到变更当帧就换菜单），
  以及拨完调用 `c.AnimationFrame()` 保证下一帧一定会画。
- **标题栏**：左侧是侧栏开关、搜索、命令面板（`command-palette` 图标）与四个菜单，中间是当前文稿的名字
  （未保存时前面有个点），右侧是窗口按钮；整行 `DragWindow()`。
- **标签栏**：属于内容卡片，标签溢出时横向滚动 + 两侧箭头（没有滚动条），末尾是新建按钮；
  切换标签时自动把它滚进视野。
- 试过把标签并进标题栏（省 38px、选中的标签向下连到卡片），实际用起来两行更好认，
  已经改回这一版。
- 一篇都没打开时**不画标签栏**（原来会留一条只有「+」的空栏），起始页直接占满卡片。
- 侧栏收起后只有一个展开入口：标题栏那个 ☰；标签栏里那个重复的已经去掉。

### 图标

`internal/app/icons.go` 里的图标全部来自 [IconMCP](https://iconmcp.com)（MIT）：
统一画在 16 格网格上、只有轮廓一种风格，`ic16()` 负责包一层
`viewBox="0 0 16 16"`、`stroke="currentColor"`、`stroke-width="1.05"` 的 `<svg>`，
颜色交给 `TextColor`。要加新图标时，用 IconMCP 的 MCP 服务
（`https://iconmcp.com/mcp`，工具 `search_icons` / `get_icon`）按含义搜一个，
把 `<svg>` 里的路径贴进 `ic16()` 即可。

### PDF 查看器：folio（纯 Go）

整页交给 **gen2brain/folio** 渲染成位图：纯 Go、无 cgo、无 wasm，Apache-2.0，
PDF 的路径/文字/图像/渐变/图案/透明/注释/图层都支持。

**为什么不是 PDFium（之前那套 wasm）**——同机同页实测：

| | PDFium（wasm） | folio（纯 Go） |
| --- | --- | --- |
| 打开（含初始化） | 1.85 s | **0.5 ms** |
| 150 DPI 单页 | 26.4 ms | **3.8 ms** |
| 300 DPI 单页 | 98.4 ms | **15.3 ms** |
| 依赖 | go-pdfium + wazero + wago + go-plugin（6MB wasm） | 只有 `x/net` |
| 中文（内嵌子集字体） | 正确 | **正确**（与 PDFium 逐像素差 0.87%，全在抗锯齿） |

**已知缺口**：PDF 只引用标准 CJK 字体（`STSong-Light` + `UniGB-UCS2-H`）而自己不嵌字体时，
folio 缺 Adobe CMap 会出乱码；PDFium 的 wasm 构建同样画不出来，所以不算退步。
这类老 PDF 要正确显示，得自己补 CJK CMap 与系统字体回落。

渲染按 `(页, DPI)` 缓存，只留最近 6 张；DPI = 96 × 缩放比（夹在 36–400）；
页宽按点（1/72 英寸）算，`适应宽度` 与百分比缩放和图片查看器共用一套口径。
#### 大纲

标题按级别搭成树（比前一个级别深的挂到它下面，跳级也能挂住），渲染方式和目录树一致：
行首的三角点一下折叠，点标题本身跳转（`jumpToHeading`）。折叠状态按「文稿路径 + 标题路径」
存在 `outlineCollapsed` 里，路径由各级下标拼成（`0`、`0.1`、`0.1.2`），所以同一份文稿
重开还认得。顶部两个小按钮是「折叠 / 展开」全部。

#### 全文搜索

`internal/app/search.go` + `pdfindex.go`：Markdown / 纯文本按 mtime + size 缓存正文与小写副本，
PDF 缓存每页文本（最多 50 页）；查询少于 2 个字直接返回，避免全库扫描。

命中的跳转分两种：PDF 滚到那一页；Markdown 切到富文本模式，把词交给编辑器的
`FindText(query)` —— 它会打开查找框、选中第一处并滚过去，回车继续往下跳。
搜索面板（`Ctrl+K`）里「正文」一节与文件名结果并列，各条带「第 N 行 / 第 N 页」与片段。

#### 缩略图与批注

左侧面板（工具栏的方块按钮开关）两个页签：**缩略图**（按 124 DIP 宽渲染、点一下滚到该页、
当前页描边）与**批注**。

批注存在 PDF **旁边**的 `xxx.pdf.papero.json` 里，不写进 PDF 本体：改 PDF 要重写整个
文件结构（交叉引用表、流对象），风险大、各家阅读器兼容性也不一；旁注文件更好同步、
更好回退，删掉最后一条批注时文件一起删除。

一条批注 = 某页的一段字符区间 + 颜色 + 备注。选中文字 → 工具栏「高亮」→ 加一条；
点已有高亮会选中它并在面板里显示备注框（可改颜色、可删）。四色：黄绿蓝粉。

#### 连续滚动

所有页竖着排进同一个 `ScrollBoth`（外面套一个 `Clip` 的盒子量视口——注意
`ScrollBoth.Bounds()` 给的是**内容框**，拿它算可见范围会把整篇都当成可见）：每页算好 y 偏移（`pdfPageGap` 间距），
内容总高 = 累计；**只渲染视口内那几页**（前后各多算一页缓冲），其余留白占位，
否则一份 100 页的 PDF 会一次渲染 100 张位图。

翻页按钮与页码输入不再是「切换页」，而是滚到那一页（`pdfScrollToPage`）；
工具栏显示的页码取视口中心所在页。

#### 文字层（选中 / 复制 / 查找）

选区是**文档级**的：`pdfPos{Page, Char}` 从一处到另一处，所以能跨页选中；
每页只画落在自己身上的那一段（`pdfRangeOn`）。

交互不落在页面上，而是盖在整个长卷上的**一层透明输入层**（`pdfInput`）：
跨页拖动时「按钮还按着」的状态不会因为换页而丢失（早先按页挂输入，换页就断）。

位图不参与交互，交互落在**页面盒子**上：`Doc.Chars(page)` 从 folio 的
`StructuredText()` 取每个字符的框（页面空间、点、左上原点，和位图同一套坐标），
乘上缩放比就是屏幕矩形。

- **拖选**：`PressedInside()` 定锚点、`Pressed()` 期间移动焦点（`pdfHitChar` 按
  「行差权重 ×6 + 横向距离」找最近字符，宁可横向跑远也不跳行）
- **高亮**：相邻同行的字符合并成一条矩形（`pdfSelectionRuns`），一页几千字也只画几十块
- **复制**：`Ctrl+C` 取选区文字（换行处补 `\n`）写剪贴板；`Ctrl+A` 全选本页；`Esc` 取消
- **查找**：`pdfSearch` 把每页字符拼成 rune 序列（跨行插 `\n`），**按字符下标**匹配
  （中文一个字三个字节，用字节偏移映射会错位），记录 (页, 起, 止)，命中处画橙色高亮并自动选中
- **跳转**：`pdfScrollToSelection` 用 `ScrollState.ScrollTo` 把命中行滚到视口上方三分之一处；
  换页时先 `pdfLoadChars` 重取字符再设选区（否则下一帧的重载会把选区清掉）
- **连击**：自己数（400ms 内同一点再按算一次连击）——双击选词（`pdfWordRange`：
  西文按字母数字连写、中文按连续汉字串），三击选段（`pdfParagraphRange`，按 `Block`）
- 工具栏里的「查找」展开输入框，回车搜索、左右箭头跳上一处/下一处
- **全局搜索**：`pdfIndexFor` 把每份 PDF 的每页文本缓存起来（按 mtime+size 失效，最多索引
  前 50 页），快速搜索里多出一节「PDF 内容」，点一条就打开那份 PDF 并滚到该页

### 图片与 PDF 查看器的工具栏

样式照 Nexus 的 `.nexus-*-toolbar`：32 高、底色与标签栏同色（连成一条「文档头带」）、
按钮一律 24×24 圆角 4 只有图标、输入框 4ch 等宽居中、分隔线 1×16 留 5。

两者共用一套小积木（`viewertool.go`），所以手感一致：

- `toolbarBar`：32 高的横条 + 下沿细线，左边视图控制、右边一行等宽灰字信息。
- `toolSep` 分隔两组控件；`toolButton` 是 24×24 圆角 4 的图标按钮，
  `on` 为真时「浅底 + 强调色」（对应 Nexus 的 `aria-pressed`），悬停只变色。
- 图标：适合窗口用「四角括号」（放大到填满），适合宽度用「一张纸 + 水平箭头」；
  `1:1` 这种用文字最说得清，所以它是同尺寸的文字按钮（`toolTextButton`），样式与图标按钮一致。
- 输入框里的文字居中（`TextAlign(ui.Center)`——`Center()` 是元素在父容器里居中，不是文字居中）。
- **缩放只有一个数**（参考 Nexus 的 `viewer/zoom.ts`）：`适应窗口` / `适应宽度` 不是状态，
  而是**动作**——按下时把 `fitZoom` / `fitWidthZoom` 算出的倍率写进 `zoom`，
  所以输入框里永远显示真实百分比（点「适应窗口」会显示 87% 这类数字，点「1:1」显示 100）。
  上下限 10%–800%，步进 25 个百分点，保留两位小数避免 `1.2499999`。
- `zoomStepper` 是「− [150] % +」：中间那一格是**可以敲的输入框**（回车生效，
  失焦时刷新回真实值）；`parseZoom` 接受 `150`、`150%`，空回到 100%。
- 图片：`适应窗口 / 1:1` · `− [150] % +` · 右侧「1920 × 1080 · 1.2 MB」。
- PDF：`‹ [3] / 12 ›` · `适应宽度` · `− [150] % +` · 右侧文档标题——
  页码同样是输入框，回车跳到那一页，超界自动夹到首尾。

### 设置（`settings.go`）

设置是一个**独立窗口**（`mygo.NewWindow`，记住窗口尺寸），标题栏**自绘**：
`TitleBarStyle: TitleBarHidden` + `TitleBarHeight: 38`，自己画一行「设置」与
最小化 / 最大化 / 关闭（复用 `windowButtons(c, pal, win)`，参数化窗口），
整行 `DragWindow()` 可以拖窗口。没有窗口的环境（测试、无头）退回主窗口里的浮层。
窗口内是「左侧导航 + 右侧内容」两栏，按使用场景分七页：

| 页 | 放什么 |
| --- | --- |
| 通用 | 知识库位置与规模、主题（跟随系统）、字号、界面语言 |
| 编辑器 | 默认显示方式（块 / 分栏 / 预览 / 源码）、阅读宽度、实时排版、图谱窗口，以及写作操作速查 |
| 主题 | `internal/theme`：base16 十六色种子 → 派生 token，`chrome` 只做「部位→token」的映射 |
| 侧栏 | 侧栏宽度、最近打开、顶部动作的显隐与顺序 |
| 同步 | 启用、自动拉取、远端类型（文件夹 / GitHub / 本库仓库 / WebDAV）与对应字段、忽略规则，以及立即同步 / 从云端拉取 / 测试连接 |
| 插件 | 已安装插件的启用开关 |
| 关于 | 版本、平台、知识库与配置目录、致谢 |

每一页的选项都是**同一种块**：一行 52 像素，左边是名字（12.5）与说明（10.5，
放不下就省略号），右边是这一项的值或控件，行间一条 1 像素分隔线，整组包在圆角卡片里。
`field` 画这一行、`fields` 把它包成卡片；侧栏页那张「顶部动作」列表走 `fieldWith`
（左端多一个拖动手柄），因为行由 `ui.List` 生成、只画看得见的那几行，分隔线的计数
直接用行号而不是自增变量。布尔项一律用开关（右对齐），勾选框只出现在列表和菜单里。

所有改动立即写入配置文件（`改动立即保存` 那行说明），底部的「完成」只是关窗。
页面状态记在 `App.settingsPage`，下次打开还停在那一页。

### 块编辑器：整体移植 ArcMD 的 `internal/editor`

不再自己用「每块一个小编辑器」拼：`internal/editor`（55 个文件、约 23.8k 行）整个搬了过来，
整篇一个缓冲区，块选择、输入法、剪贴板、自动配对、斜杠菜单、表格、公式、Mermaid 都是它自带的。

接缝只有三处（`internal/app/editor.go`）：

- **模型**：编辑器内部用的就是 `document.Document`，和 `richdoc` 是同一套类型
  （移植时把导入改名为 `document "papero/internal/richdoc"` 即可），所以大纲、链接图这些
  读 `tab.rich` 的代码不用改；
- **保存**：`richdoc.ExportMarkdown(tab.edit.Doc)` 写回 `tab.buf`，脏标记与自动保存照旧；
- **颜色/宽度**：把 Papero 的调色板翻译成 `editor.Page`；`Options.Width` 必须给实测的
  可用宽度（给 0 会被当成 0，正文挤成一条线），`Column` 用设置里的阅读宽度。

一起搬来的还有 `internal/i18n`（见下文「多语言」）、`internal/mermaid`、`internal/wikitext`
（ArcMD 的 wiki 文本助手，和 Papero 自己的 `internal/wiki` 并存，API 不同）。

旧的「每块一个 editor.State」实现（`blocks.go` / `blocksel.go` / `slash.go` / `blockmenu.go`）
**已删除**（备份在 `ref/_removed/old-blocks/`）。下面是它踩过的坑，留作记录：

### 白板（Excalidraw 子集）

`internal/board` 只管数据（`.excalidraw` 的 JSON），绘制在 `app/board.go` 用 Painter 完成，
不加载任何网页。元素字段与 Excalidraw 同名，**不认识的字段用 `Extra` 原样留着**，
所以双向互通。

手绘抖动在 `app/boardrough.go`：每条边拆成 4 段各自偏移、叠两遍（第二遍更细），
长边按垂线方向鼓一点。随机数用元素自带的 `seed` 播种的 LCG——确定性是硬要求，
否则每帧都在抖，像泡在水里。

箭头绑定（`internal/board/bind.go`）不存端点坐标，只存「粘在哪个形状上」
（`startBinding` / `endBinding`，Excalidraw 同名字段）；每次重算时用「另一端的方向
→ 形状边界」求交点（矩形按比例、椭圆按参数方程、菱形按四边求交）。所以形状移动、
缩放都不用额外处理，`RebindAll(id)` 一次就同步。

图片照 Excalidraw 的做法：二进制以 dataURL 存在 `files` 里，元素只记 `fileId`。
渲染时按 fileId 缓存解好的位图（每帧 base64 解码会卡），导出 SVG 直接写 `<image href>`，
所以一张 SVG 是自包含的。

形状里的文字照 Excalidraw 的结构：一个 `text` 元素带 `containerId` 指向形状，
形状在 `boundElements` 里反向记一笔。文字始终居中（`CenterContainerText`），
形状一动就重算一次，所以不存在「文字与形状对不上」的状态。

改接的交互在 `boardInput` 里：按下时先用 `EndpointAt` 判断是不是抓住了端点（容差
按缩放折算成 10 像素），抓到就走「拖端点」分支——先解绑那一端，拖动时用
`SetEndpoints` 重写两端，松手再 `ShapeNear` 吸附或保持自由。

选择集是 `[]string`（不是单个 ID）：多选、分组展开（`ExpandGroup`）、整体平移都在这一层。
拖动多元素时按「按下那一刻各元素的位置 + 同一个位移」算，避免累积误差。

拉角缩放记下按角前的包围盒（`boardResizeBox`），拖动时按角号重算，翻转时把宽高钳到最小 8。

撤销用快照栈（`Clone()` 深拷贝元素，含 `Points` 与 `Extra`），不是操作日志：
白板元素少、单步改动大，快照更简单也不会漏。

### 旧实现（已删除）：每块一个小编辑器

**编辑状态绝不能随手丢掉。** `commitRichBlock` 每次按键都会把这一块的 Markdown
重新导入模型，早期实现顺手把 `richStates[i]` 置空——下一帧重建编辑器时光标回到 0、
输入法的组合被打断，表现就是「打一个字光标跳到最前面、中文打不出来」。
现在只在**结构性变化**（回车把一块拆成多块）时挪状态，普通输入原地保留，
选中的 `editor.State` 带着光标、选区与组合状态一起活下来。

块上的操作（`blockmenu.go`）：右键菜单提供插入、复制一块、上移 / 下移、转为、删除；
块选择支持 Shift 点选范围、Ctrl+A 全选所有块、Ctrl+C 复制选中块的 Markdown、
Delete 删除。

### 富文本块编辑器（改用 ArcMD 的模型）

块编辑器读的是 `internal/richdoc` 的富文档模型——**直接改编自 ArcMD**
（`internal/document` + `internal/editor/markdown.go`，MIT，见 NOTICE）：

- **模型**：`Document.Blocks` 是带样式的块（paragraph / heading / bullet / numbered /
  task / quote / code / table / math / callout / toggle…），每块由若干 `Run` 组成，
  `Run.Style` 记 bold、italic、strike、code、link、highlight、script。
- **无损往返**：`ImportMarkdown` 保留原文（`ImportSource`），`ExportMarkdown` 按源块
  逐块写回——**没改过的块按原字节输出**，改过的才重新序列化。这是 ArcMD 的做法，
  比自己维护「标记 + 内容 + 空行」三段式（原来 `internal/mdedit` 的做法，已删除）可靠得多。
- **交互**：Typora 式——**失焦的块显示排版，聚焦的块显示源码**。点一块进入编辑，
  Esc 或点到别处退出；编辑结果解析回模型后整篇导出写回缓冲区，自动保存照旧。
- **渲染**：富文本用 `ui.RichText` + `ui.Span`（粗体是 `Weight: 700`，行内代码是等宽字体
  加底色与圆角，链接与双链用强调色），块级元素（表格、代码块、引用竖线、复选框）
  由 `blocks.go` 自己画。双链在正文里渲染成蓝色文字（去掉 `[[ ]]`）。
- **块内回车**：编辑时换行会让这一块解析成多块，自动拆分。

- **编辑手感**：↑/↓ 在首行 / 末行时走到相邻块；行首退格把这一块并进上一块；
  Esc 或点到别处退出编辑。
- **图片块**：从知识库读文件、`ui.DecodeBitmap` 解码后按块宽绘制，失败给占位。
- **公式块**：`internal/tex` 负责把 TeX 排成「盒子 + 绘制指令」，`richMath` 再把它画出来——
  `rule`（分数线）与 `path`（根号、括号）交给 `Painter`，`text` 用绝对定位的 `ui.Text`，
  这样斜体、粗体、上下标字号都能保住。认不出的命令（tex 会标 `Error`）画成灰字，
  排版失败则退回等宽源码，不让用户看不见内容。

- **行内公式**：`$…$` 换成「行内对象」——`ui.Span` 的 `ObjectWidth/ObjectHeight/ObjectDescent`
  让它占一个盒子（`\uFFFC`），行内代码里的 `$` 不参与；再用 `Element.DrawObjects`
  在每一处对象上把公式画出来。局限：`Painter` 没有字体样式参数，行内公式的变量
  按正体画（块级公式用绝对定位的 `ui.Text`，所以那里斜体是对的）。

- **`/` 命令菜单**（`slash.go`）：版式参考 ArcMD 的斜杠菜单——没输入时顶部是一排
  **图标网格**（6 列，正文 / 标题 1–3 / 无序 / 有序 / 待办 / 引用），下面是「更多」里的
  代码块、公式、分隔线、表格。每类图标有自己的颜色（标题蓝、列表靛、代码绿、公式青、
  分隔线橙），右侧标出 Markdown 快捷写法，底部一行键盘提示；面板放不下时会翻到上方，
  列表超过 320 就内滚动。输入即过滤（带拼音与英文关键词，比如 `/biaoti`、`/code`）。
  插入不走另一套逻辑——就是把这一块的源码换成 `## ` / `- [ ] ` 之类的前缀，再交给
  richdoc 重新解析。菜单打开时给编辑器换一份按键表（`slashBindings`），把 Enter 与
  上下键让出来，免得既选菜单又往正文里插换行。

- **拖动排序**（照 ArcMD 的块拖动做的）：每块左侧有一个 grip 把手（常驻占位、悬停才显形，
  这样拖到别的块上时把手不会消失、拖动能继续——一开始按需渲染就踩到了这个坑）。
  把手用 mygo 的 `Draggable`（`Axis: Vertical`）接住指针，`Dragged()` 为真即进入拖动；
  每帧记下各块的矩形，用「被拖块的中点落在哪一块上」算落点；松开时 `DragEnded()`
  触发，把块从原位置摘出来插到目标位置，再 `flushRich` 写回 Markdown。
  视觉上被拖的块淡色高亮，落点画一条强调色细线（ArcMD 是 `MoveBlock` + 2px 强调线，
  思路一样）。

- **点哪落哪**：点一块进入编辑时，光标落在点到的位置而不是行首。做法是拿点击坐标
  在 `ui.ShapeRichText` 的排版上做 `IndexAt`，得到「第几个可见字符」，再用
  `visibleToSource` 顺着 Markdown 源码数过去（跳过 `**`、`` ` ``、`[[ ]]`、行首的 `#`/`> `/`- `），
  换算出源码里的字节位置。

- **多选块**（`blocksel.go`）：Shift 点击按范围加选（`ClickModifiers` 判断 Shift），
  选中的块淡色高亮；Delete / Backspace 一起删（`deleteSelectedBlocks`），
  拖动其中一块时整组跟着走（`finishBlockDrag` 里按组摘出再插入），Esc 清空。
- **块内拖选文字**：按下即进入编辑并把锚点放在按下的位置，之后指针移动就按位置
  扩展选区（`extendTextSelection`）——用的是按下那一帧缓存的排版信息算位置，
  因为这时块已经从排版变成了编辑器。为此编辑态的块也套在同一个 Row 里，
  行元素保持稳定，按压状态才不会丢。
- **嵌套拖拽**：richdoc 的嵌套列表是「扁平的块 + `Indent`」，所以嵌套就是改缩进。
  拖动时指针停在哪一行、横向偏多少（`dragIndentAt`）就决定缩进几层；缩进比目标深
  就插到目标之后（变成它的子项）。键盘上 Tab / Shift+Tab 也能调缩进
  （`changeIndent`，这两键的默认绑定在这类块上被摘掉了）。

还没做的：块的多选区间用鼠标拖出来（现在靠 Shift 点击）、折叠块的折叠展开。

### 为什么仍然保留分栏

块编辑器解决了「写」，预览解决了「读」：表格、图片、公式、脚注这些在块里还是源码，
想看清楚就切到预览。分栏把两者并排，源码与渲染对照着改，适合改长文。
三种模式（块 / 分栏 / 预览 / 源码）随时切换，Markdown 始终是唯一真相。

所见即所得需要「富文本块模型 ↔ Markdown 无损往返」：块结构、增量排版、光标映射、
IME 组合、撤销粒度都要重做（ArcMD 与 Leafmark 各花了几万行）。分栏把 Markdown 源码
作为唯一真相，正确性一目了然，也不会有「另存一份私有副本」的问题。

架构上给它留了位置：`content.go` 里的 `markdownTab` 是唯一的分派点，
将来的块模型编辑器作为 `tab` 的另一种渲染方式接进来即可，不需要动
`vault`、`sync`、`plugin`。

## 多语言

界面原文是中文，`internal/i18n/messages.go` 那张表把它说成英文。

**机制**：每条文案有一个稳定的 key，和两种说法：

```go
"pdf.tool.prev_page": {"上一页", "Previous page"},
```

`i18n.T("pdf.tool.prev_page")` 按当前语言取一句，查不到就返回 key 本身。
界面上冒出 `pdf.tool.prev_page` 很难看，但比空白好查，而且测试会先拦下来。

key 的形状是 `<域>.<区块>.<元素>[后缀]`：全小写、点分段、段内下划线。域对应界面上的一块
（`settings` / `pdf` / `board` / `kind` …），后缀只有四个——`_hint` 说明文字、
`_label` 无障碍名或字段名、`_tooltip` 悬停提示、`_empty` 空状态。

**为什么不用「中文原文当 key」。** 那是 gettext 的老做法（msgid 就是源语言原文），
零成本起步，但有三个代价：改一个字等于换了一个 key，译文静默丢掉；同一个中文在不同
地方意思不同（「分栏」在块类型里是 Columns、在显示方式里是 Split），原文分不开；
最要紧的是**翻译协作**——key 是中文，译者必须懂中文，还拿不到上下文。
命名 key 把「标识」和「文案」拆开，这三个问题一起消失，代价是要给每条起名字。

**语言从哪来**：只有一个来源，`config.Settings.Language`（空 = 中文，`"en"` = 英文）。
`Run()` 在建库之前设一次（新建知识库的欢迎文档要用它决定写中文还是英文），
`App.view()` 每帧开头再同步一次。设置页只写配置、不直接切语言，所以不会出现
「切换的那一帧上半截中文、下半截英文」。

没有「跟随系统」这一档：探测系统语言要平台 API（Windows 的 `GetUserDefaultUILanguage`），
做不到就不装作能做，猜错比不猜更糟。空值就是中文，和从没写过一样。

**四个约定**：

1. **数据表里存 key，不存中文。** 标注样式、颜色名、代码语言这些表（`AnnotationNames`、
   `colorNames`、`codeLanguages`）的值都是 key，画的时候才 `T`。包级变量里调 `T` 也不行——
   那只会按 init 时的语言算一次。
2. **同一句中文在不同语境就是两条 key。** `board.tool.select` 是工具栏的 Select，
   `settings.theme.picker_label` 是选颜色的 Choose，各说各的，不需要语境参数。
3. **单复数用两条 key，不带 ngettext。** 优先写「标签: 数值」（`Documents: 1`），
   绕不开的句子才用 `Tn(n, ".one", ".other")`——中文两条通常一样，英文一条
   `1 document`、一条 `3 documents`。颜色的深色变体也是两条完整文案
   （「深红」/ "Dark red"），不靠截字拼接。
4. **领域包可以 import `i18n`，不能 import `ui`。** `vault.Kind.Label()` 返回的是界面文案，
   就在那里 `T` 掉；渲染仍然只能在 `app` 里做。

**覆盖**：`app`、`editor`、`vault` 三处的界面文案全部走过 `T`（合计 781 处调用、677 条文案）。
唯一的豁免是 `shot.go`——它是 `-shot` 调试工具，写的是样例库与终端输出，界面上看不到。

**日期跟界面语言走。** `i18n.Date(t)` 中文写「2026年11月21日」、英文写 "Nov 21, 2026"，
`i18n.Tag()` 给需要 BCP 47 标签的地方。显示日期一律走它们——跟着系统语言跑，
中文系统的英文界面里就会冒出「11月21日」。

**五道检查**：

- `i18n.TestMessageShape`：key 的命名形状、每条都要有中文和英文。
- `i18n.TestMessageKeysExist`：扫全仓库 `T` 的字面量 key，表里没有就直接失败。
- `i18n.TestPluralPairs`：`.one` 与 `.other` 必须成对，缺一条界面上就露出 key。
- `i18n.TestEnglishHasNoChinese`：英文里不许出现汉字与中文标点。源文案是中文，
  抄一条进 en 字段很难自己发现，英文用户却直接看得到；故意要显示中文的走允许清单。
- `app.TestNoUnwrappedChinese`：只扫 `app` 包的**函数体**，出现任何中文字面量就失败。
  包级 `const`/`var` 不算（那是数据，翻不翻由用到处决定）。

## PDF：folio 渲染 + 文字层

`internal/pdfview` 只是 folio 的薄封装（约 170 行）：`Open / Pages / Size / Render / Text / Chars`。
页面由 folio 光栅化成位图（路径、文字、图像、渐变、图案、透明、注释都能画），
交互靠 folio 的 `StructuredText()` 给出的**字符框**。

早期写过一套自研解析器（`internal/pdf`，2,577 行：xref、过滤器、字体与 ToUnicode、
内容流解释器、图片解码），按坐标重排文字——字体、矢量、图形一律对不上，版面一复杂就散架，
已在 0.1.10 删除（备份在 `ref/_removed/internal-pdf/`）。

## 双链与知识图谱

`internal/wiki` 负责两件事：解析 `[[…]]`，以及维护整个知识库的链接图。

- **解析**（`Parse`）：跳过代码围栏与行内代码，支持 `[[目标]]`、`[[目标|别名]]`、
  `[[目标#标题]]`；围栏那一行整行跳过，否则闭合围栏的 ``` 会被误当成行内代码的起点。
- **解析目标**（`resolve`）：先按相对路径找，再按标题（文件名去扩展名）找，
  同目录优先、其次层级最浅；找不到就返回空——那意味着「这篇还不存在」。
- **改写**（`Rewrite`）：预览前把双链换成 `[文字](wiki:编码后的目标)`，
  这样 `ui/markdown` 把它当普通链接渲染，点击仍然回到 `App.linkHandler`。

- **补全**（`complete.go`）：编辑器里输入 `[[` 时，每帧检查光标是否在未闭合的双链里
  （同一行、`[[` 之后没有 `]`、`|`、`#`），是就调 `editor.State.ShowCompletions`
  弹出候选——弹层的位置、键盘选择、前缀过滤都由编辑器负责，我们只提供候选：
  库里已有文稿（按名字前缀、链接数排序）加一条「新建」。

- **改名时修引用**（`App.rewriteLinksAfterRename`）：重命名之前先抓一份链接图，
  改完之后逐篇扫 `[[…]]`，用旧图判断「这条链原本指向哪篇」，指向被改名的那篇就改写：
  路径写法继续写路径（保持原来「从库根算」还是「从当前目录算」的风格），
  只写标题的写法换成新标题；别名与锚点原样保留。目录改名时只改路径写法的引用，
  标题写法的引用本来就还能解析。改到的文稿如果正开着，编辑器内容也一起更新。

- **悬停预览**：侧栏「链接」页的行有真实元素，指针停上去时把目标文稿的标题、
  路径与开头几行显示在面板底部的固定预览区。做成固定区域而不是浮层，是因为
  `ui.Overlay` 会挡在指针前面，让「悬停离开」永远检测不到（踩过这个坑）。
  预览里的行内链接没有悬停回调（`ui/markdown` 只给 OnLink 与 LinkMenu），
  所以那里改用右键菜单：打开 / 在文件管理器中显示 / 新建这篇 / 复制链接。
- **断链批量新建**（`App.createMissingLinks`）：把「还没创建」里的名字一次建成空文稿。
- **删除前提醒**（`App.trash` / `trashView`）：移到回收站之前查反向链接，
  有引用就先弹确认框，列出会被断链的文稿（点名字可以直接打开看看）。
  断链不是灾难——它会出现在「链接 › 还没创建」里，点一下就重建同名文稿。

链接图（`Graph`）给出每个文稿的出链与反向链接，界面据此画出：

- 侧栏「链接」页：反向链接（带出处那一行的摘要）、出链、还没创建的链接（点击新建）
- 状态栏：当前文稿的反向链接数
- 知识图谱：交给 Onevra 的 `components/graph`（关系图谱组件）。Papero 只提供数据：
  节点 ID 用相对路径、`Group` 用顶层目录（同目录聚在一起并按组分配色相）、
  `Weight` 取链接数（决定节点大小）、边来自双链；`Open` 回调里打开对应文稿。
  布局、镜头、悬停高亮、滚轮缩放、拖动平移、入场动画都由组件负责——
  自己写一版力导向既费事又不如它稳。零散的（没有任何链接的）文稿也会画出来，
  用单独的「孤立」配色，方便看出「哪些还没连起来」。

图谱有两种打开方式，由设置的 `graphMode` 决定：`embed` 在主窗口的浮层里画
（压暗背景 + 圆角面板），`window` 用 `mygo.NewWindow` 另开一个窗口。
两者共用 `graphBody`，区别只在外面套什么壳；浮层模式点节点后自动收起，
独立窗口则留着方便连续看几篇。没有主窗口时（例如测试）一律退回浮层。

链接图在文件树变化（`refresh`）或保存后重建，用 `stamp`（文件树的路径+大小+时间指纹）
判断是否需要重算，避免每帧读全库。

## 白板：内置功能

白板是 Papero 的内置功能，不是插件。数据层 `internal/board` 与界面无关：
读写 Excalidraw 的 JSON、增删元素、命中测试；绘制与交互在 `app/board.go`，
用 `Painter` 画矩形、椭圆、菱形、箭头与文字。

一开始它是以「内置插件」的形式做的，但那样只是多一层没有意义的间接：
它反正要编译进同一个二进制，又要和文稿列表、标签、保存流程长在一起。
所以现在所有第一方能力（Markdown、PDF、Word、白板）都是核心代码，
插件只留给第三方扩展——详见 [plugins.md](plugins.md)。

## 同步

`internal/sync` 做文件级三方同步：每个文件记住「上次同步时的本地摘要与远端摘要」，
与当前状态比对后决定上传、下载、删除还是留冲突副本。远端是一个接口，
现在有四种实现：文件夹、Git 仓库、库自己的 git 仓库与 WebDAV 网盘。自建 HTTP 服务已移除（备份在
`ref/_removed/self-hosted-sync/`），详见 [sync.md](sync.md)。

## 自更新

`internal/update` 从 GitHub Releases 取新版本，然后换掉正在运行的 exe。它不 import
`ui`，也不管界面：查、下、换、清，四件事各一个函数，界面那层（`internal/app/update.go`）
只维护一个状态机。

- **来源**：`https://api.github.com/repos/iazhan/Papero/releases/latest`。只用官方
  release，所以草稿和预发布天然被排除；404 当作「还没发过版本」，不是错误。
- **认哪个文件**：`papero-<goos>-<goarch>[.exe]`，和 `release.yml` 里的产物名一一对应。
  这个平台没有对应包时明确报错，不静默当「已是最新」。
- **校验**：下载到 exe 旁边（同卷才能 rename），比字节数，再比 release 里那份
  `SHA256SUMS.txt` 里的摘要。没有签名——这条链的信任起点是 GitHub 仓库本身；
  要换成签名发布，只换 `updater` 的实现，状态机不用动。
- **换文件**：Windows 上运行中的 exe 不能覆盖但可以改名，所以顺序是旧 exe 让位成
  `.<name>.old-<pid>` → 新的就位，失败就把旧的改回来。让位出来的旧文件在下次启动时
  删（`cleanupUpdate`，在 `Run()` 里）。
- **能不能换**：取决于 exe 所在目录可不可写。mygo 的安装包把它装在
  `%LOCALAPPDATA%\Programs\Papero` 就是为了这一点；绿色版放在只读目录时，换文件那步
  会失败并说清原因。
- **节奏**：启动 20 秒后查一次，之后每 6 小时；设置里可以关掉自动检查（手动仍可用）。
  查到之后**不自动下载**，要用户点一下——24MB 的下载不该在用户不知情时发生。
- **重启**：换完先 `saveAll()`，再 `mygo.App.Relaunch()`。

### 更新提示与更新日志

- **侧栏底部一张卡片**（`updateBanner`，在「设置」上面）：有新版本写「有新版本 vX ·
  查看更新日志」，刚更新完写「已更新到 vX」。点开是更新日志浮层。不做弹窗——用户正在
  写东西时突然盖一层是最招人烦的做法。
- **更新日志浮层**（`notesView`）：从当前版本到目标版本，**中间每一版**的日志按版本
  从新到旧列出来（`update.Notes` 翻 `/releases` 分页，跳过草稿与预发布，最多 40 条，
  超出的报总数）。底部是下载 / 重启并安装 / 关闭。
- **正文自己摊平**：`noteLines` 把 release 的 Markdown 压成纯文本行——标题留字加粗、
  列表变 `•`、链接留文字、PR 地址缩成 `#123`。浮层没有 Markdown 渲染器，也不该为
  一段日志拉一个进来。
- **双语**：release 正文是一份双语 Markdown——英文在上，`<!-- lang:zh -->` 一行之下
  是中文（`internal/update/lang.go` 的 `InLang` 按界面语言取一半）。客户端存的是原文，
  切开是在渲染时做的，所以切换语言浮层立刻跟着变，不用重新去拉一遍。老日志没有分界线，
  原样显示。
- **「刚更新完」靠配置**：`Settings.LastVersion` 每次启动写一次；和当前版本一比就知道
  这次是不是升级上来的（升级才提示，全新安装、同版本、降级都不提示），提示用的日志是
  (上次版本, 当前版本] 这一段。

```sh
go test ./...
```

- `vault`：类型识别、扫描顺序、路径越界拒绝、原子写入、回收站；

  （建目录、中文与空格路径、条件写被拒、鉴权）；本库仓库模式用本地 bare 仓库验上传/
